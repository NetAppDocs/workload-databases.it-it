= Registra le risorse in NetApp Workload Factory per i database
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Registra istanze per Microsoft SQL Server e database per Oracle così puoi gestire le risorse, creare database e cloni sandbox, eseguire l'analisi dei log degli errori e ottimizzare le configurazioni in NetApp Workload Factory for Databases.

È possibile registrare le risorse solo se vengono eseguite su FSx for ONTAP file system storage.



[[about-the-task]]
== Informazioni sul compito

La registrazione di un'istanza (SQL Server) o di un database (Oracle) prevede due passaggi: autenticazione dell'istanza o del database e preparazione. L'autenticazione è il processo di verifica delle credenziali per l'istanza o il database. La preparazione include l'installazione dei moduli AWS, NetApp e PowerShell sull'istanza o sul database, per soddisfare i requisiti minimi per le funzionalità di Workload Factory for Databases come link:create-database.html["creare un database"], link:create-sandbox-clone.html["creare una sandbox"], link:analyze-error-logs.html["analisi del registro degli errori"] o link:optimize-configurations.html["la valutazione well-architected"].

Workload Factory supporta solo la registrazione e la gestione di istanze Microsoft SQL Server e database Oracle. A seconda delle credenziali dell'account AWS selezionate in Workload Factory, gli host PostgreSQL vengono visualizzati nell'Inventory. Attualmente, Workload Factory supporta istanze PostgreSQL non registrate in esecuzione solo su sistemi operativi Amazon Linux.



[[before-you-begin]]
== Prima di iniziare

Devi fare quanto segue prima di registrare un'istanza o un database:

* Assicurati che gli host delle risorse che desideri registrare siano presenti nell'inventario. link:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["Concedi le autorizzazioni per le operazioni e la bonifica"^] nel tuo account AWS.
* Associa un collegamento al file system FSx for ONTAP che ospita le risorse che vuoi registrare. link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-link.html["Scopri come associare un link esistente o crearne e associarne uno nuovo."^] Dopo aver associato il collegamento, torna a questa operazione.




[[registering-an-instance-in-a-private-network]]
=== Registrazione di un'istanza in una rete privata

Per registrare un'istanza o un database in una rete privata senza connettività esterna, rendi disponibili gli endpoint richiesti nella VPC e associarli alle subnet pertinenti. Consenti la porta 443 nel Security Group per gli endpoint dell'interfaccia.

* `S3 Gateway/endpoint`
* `ssm`
* `ssmmessages`
* `fsx`
+
Se si utilizza un proxy server per le connessioni EC2 outbound, consentire l'accesso a questi domini per le operazioni di gestione:

* ``.microsoft.com``(SQL Server)
* ``.powershellgallery.com``(SQL Server)
* ``.aws.amazon.com``
* ``.amazonaws.com``




[[register-a-microsoft-sql-server-instance]]
== Registra un'istanza di Microsoft SQL Server

La registrazione di un'istanza si articola in due fasi: autenticazione dell'istanza e preparazione. Puoi registrare una singola istanza o più istanze.

Workload Factory supporta la registrazione per Failover Cluster Instance (FCI) e Standalone deployment per SQL Server.

.Fasi
. Accedere utilizzando uno dei link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["esperienze di console"^].
. Seleziona il menu image:workloads-menu-icon.png["L'icona del menu hamburger viene utilizzata per navigare tra carichi di lavoro quali storage, eda, ai, database, vmware e amministrazione."] e quindi selezionare *Database*.
. Dal menu Database, selezionare *Inventario*.
. Nell'inventario, seleziona *Microsoft SQL Server* come tipo di motore.
. Selezionare la scheda *Istanze*.
. Selezionare per registrare una singola istanza o più istanze.
. Per autenticare le istanze (passaggio 1), eseguire le seguenti operazioni e quindi selezionare *Avanti*:
+
.. Selezionare *Usa le stesse credenziali per tutte le istanze* o *Gestisci le credenziali manualmente*.
.. Autenticare SQL Server e Windows fornendo nome utente e password.
+
Se le istanze sono autenticate, seleziona *Avanti*.



. Per Prepare (passaggio 2), assicurarsi che l'istanza o le istanze soddisfino i requisiti minimi.
+
Per soddisfare i requisiti minimi, l'istanza deve avere i moduli AWS e NetApp PowerShell e i moduli PowerShell 7 installati, e devi completare i prerequisiti per almeno una delle funzionalità elencate sotto Controllo prerequisiti.

+
.. Rivedi i prerequisiti nella *Prerequisite check view*.
+
È necessario completare tutti i prerequisiti per una singola funzionalità come *Review well-architected issues and recommendations* per registrare l'istanza.

.. Seleziona *Dettagli di configurazione* per ciascuna funzionalità per conoscere i prerequisiti della funzionalità e seguire le istruzioni sullo schermo per completare eventuali prerequisiti mancanti per una funzionalità.
+
Per abilitare Workload Factory a link:optimize-configurations.html["rivedere e correggere i problemi di architettura"], completare tutti i prerequisiti in *Esaminare i problemi e le raccomandazioni ben progettati* e *Correggere i problemi ben progettati*.



. Dopo aver completato tutti i prerequisiti, *Registra* l'istanza/le istanze.


.Risultato
La registrazione dell'istanza viene avviata. Selezionare la scheda *Monitoraggio lavori* per monitorare l'avanzamento.



[[register-an-oracle-database]]
== Registrare un database Oracle

La registrazione di un'istanza si articola in due fasi: autenticazione del database e preparazione. Puoi registrare una singola istanza o più database.

.Fasi
. Accedere utilizzando uno dei link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["esperienze di console"^].
. Seleziona il menu image:workloads-menu-icon.png["L'icona del menu hamburger viene utilizzata per navigare tra carichi di lavoro quali storage, eda, ai, database, vmware e amministrazione."] e quindi selezionare *Database*.
. Dal menu Database, selezionare *Inventario*.
. Nell'inventario, seleziona *Oracle* come tipo di engine.
. Selezionare la scheda *Database*.
. Selezionare per registrare un singolo database o più database.
. Per autenticare i database (passaggio 1), procedere come segue e quindi selezionare *Avanti*:
+
.. Selezionare *Usa le stesse credenziali per tutte le istanze* o *Gestisci le credenziali manualmente*.
.. Se i database sono autenticati, seleziona *Avanti*.
+
Se i database sono autenticati, seleziona *Avanti*.



. Per la preparazione (passaggio 2), assicurarsi che il database soddisfi i prerequisiti richiesti. Se tutti i moduli richiesti sono installati e i prerequisiti sono soddisfatti, selezionare *Next* per registrare il database. In caso contrario, seguire questi passaggi.
+
.. Rivedi i prerequisiti nella *Prerequisite check view*.
+
È necessario completare tutti i prerequisiti per una singola funzionalità come *Review well-architected issues and recommendations* per registrare il database.

.. Seleziona *Dettagli di configurazione* per ciascuna funzionalità per conoscere i prerequisiti della funzionalità e seguire le istruzioni sullo schermo per completare eventuali prerequisiti mancanti per una funzionalità.
+
Per avere Workload Factory link:optimize-configurations.html["rivedere e correggere i problemi di architettura"] per i tuoi database, completa tutti i prerequisiti elencati nelle funzionalità *Esamina i problemi e le raccomandazioni ben progettati* e *Correggi i problemi ben progettati*.



. Dopo aver completato i prerequisiti, *Registra* il database.


.Risultato
La registrazione del database viene avviata. Selezionare la scheda *Job monitoring* per monitorare l'avanzamento.

.Cosa succederà
Dopo la registrazione, puoi eseguire queste attività.

* Visualizza i database dall'inventario
* link:create-database.html["Creare un database"]
* link:create-sandbox-clone.html["Creare un clone del database (sandbox)"]
* link:optimize-configurations.html["Ottieni una valutazione completa e ben strutturata delle configurazioni del database"]
